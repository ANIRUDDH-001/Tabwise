## Durable authority and replay (SOURCE / measured scope below)

Existing Tabwise Postgres is selected after inspection of admit_version, run_transition and reserve_diagnosis. Unlike the existing reconcile lease, consumption never expires back to available. SELECT FOR UPDATE serializes competing consumers; the receipt is persisted by the same committed transaction. Same-run readback returns the original receipt with fresh:false. Another run cannot consume it. A crash or lost response after commit burns the authorization; rollback yields no committed receipt and therefore no signed launch permission. Clients never automatically retry uncertain consumption.

The server signs committed receipts with a separately provisioned Ed25519 key after checking independently authenticated caller identity. The receipt binds purpose, repository, workflow, execution SHA, actor, decision/review refs, reviewed file scope/digest, qualification digest, plan/fixtures, attempt, expiry, run identity and the coordinator's ephemeral public key. W2a purpose never substitutes for production R2 purpose. Only a fresh consume exposes a launch coordinator; readback cannot reconstruct its private key. Page spending happens before readback I/O, so an uncertain page check also cannot be retried. Each page rechecks authority state/expiry before a grant. Exact authorization ID is checked by every verifier; a matching binding under another authorization ID refuses. Revocation is checked at these boundaries; this does not claim instantaneous revocation of an already issued/in-flight grant.

The authority endpoint/authenticated identity verifier and signing-key provisioning are not deployed or configured. createPostgresAuthority maps an existing server-side client's committed w5_consume/w5_read_receipt RPC result; authenticate has no fallback and must establish the caller independently of submitted fields. Default transport refuses. No bearer token was obtained or used.
