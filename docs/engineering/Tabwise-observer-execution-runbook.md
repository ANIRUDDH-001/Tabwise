This committed procedure is preparation only. The repository ships disabled/BLOCK. Publication, activation and execution each require a separate explicit owner decision for the exact final revision and scope; agents must not perform them under implementation authorization.

1. Confirm independent preparation review and frozen R1 integrity, the exact final published commit SHA, qualification content digest, actor and owner decision reference. Any guarded-code/content-scope change requires only a minimal changed-file independent review. A new activation commit must be bound again; do not treat an older approved SHA as authorization for it.
2. Owner alone publishes/integrates the exact workflow revision onto main. Verify that checkout/setup is clean; the entry refuses before runtime loading if it is not. Do not run NVDA on a development machine.
3. After separate owner approval, configure `scripts/tabwise/qualification-status.json` with enabled=true/verdict=PASS and the exact independent reviewer/ref, owner D-number, actor, sorted `QUALIFICATION_FILES` and recomputed digest. No variable, status or credential is activated by preparing this document.
4. Manually dispatch `.github/workflows/tabwise-observer.yml` once on that main revision, with `enable_qualification=true` and the matching `owner_approval_ref`. Only initial attempt1 is permitted. Record GitHub run ID, attempt and timestamp. Never use rerun or repeat dispatch on the same approval.
5. **Delete `TABWISE_OBSERVER_APPROVED_REVISION` immediately after the first dispatch, whether it succeeds or fails.** Delete it before waiting for the outcome. Verify that it is absent and record revocation time/evidence. If deletion cannot be confirmed, request cancellation of the pending/running experiment and treat authorization as unresolved; do not dispatch again. Deletion blocks future admissions; it does not recall an already initiated key or reliably stop a job whose environment was already resolved.
6. After the run, owner resets qualification status to disabled/BLOCK in a follow-up revision. Keep the full Tabwise worker independently BLOCKED. Retain the original workflow attempt, bounded journals, result, manifest/hash and cleanup failures; do not edit or replace historical evidence. New experimentation requires a new owner decision.
